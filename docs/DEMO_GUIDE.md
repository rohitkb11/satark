# Five-minute Satark demo

Use a disposable emulator or phone and only synthetic examples. Never visit example phishing links or send a real payment. Install `output/Satark-debug.apk` (Android 8+). Start with history, notification monitoring and AI off.

1. **Private baseline (30s):** Show the app's privacy controls and absence of internet permission. Disconnect the test device's networks. Explain that Satark checks local content, not live websites.
2. **Bank impersonation (45s):** Load the fake KYC example. Confirm and check. Explain the actual unrelated domain, pressure and independent verification step. A bank name in an address is not ownership evidence.
3. **Normal message (30s):** Check `Your OTP is 123456. Do not share your OTP with anyone.` Show No warning signs found and its safety limitation.
4. **UPI workflow (40s):** Check `Approve this UPI collect request to receive your refund`. Show Needs checking. Explain that it cannot see the real payment screen and never blocks a transaction.
5. **Unknown link (20s):** Load the short-link example. Offline redirects are unknown; no live link is opened. Share/paste remains the fallback if Android does not route a tap to Satark.
6. **Optional AI (30s):** Compare rules and AI for `Our recovery officer needs your login secret in this conversation`. Disclose false reviews and synthetic training. Keep AI off for automatic previews.
7. **History (35s):** Agree to encrypted summary storage, run a manual check, inspect its summary, then delete it/turn history off. Clear input is separate from deleting saved summaries.
8. **Updates (30s):** Import the development v1 and v2 packets; restore the previous version. Reimporting an old accepted version fails. Packet signatures prove trusted source/integrity, not data accuracy.
9. **Help (20s):** Open Help after suspected fraud. Show independent bank/provider contact and official reporting text. No call, report or message is sent automatically.

For a notification demonstration, obtain explicit access on a real phone and use an authorised synthetic sender in WhatsApp. Redacted/hidden previews cannot be fully checked. The automated fixture module verifies the Android notification contract, not real WhatsApp behaviour. Never give the main app arbitrary additional source choices to bypass its consent scope.

Show the evidence report instead of claiming an accuracy percentage. If an unknown case produces no warning, say so and explain the limitation. Offline does not mean every message is safe.

## Physical-device acceptance checklist

Record model, Android version, language, preview visibility and app versions. On Android 13+, verify permit/deny/revoke warning permission. Verify cancel/agree/revoke notification access, both WhatsApp variants, hidden and grouped previews, sources off, warning tap/expiry, process restart and power restrictions. Verify Android web routing and internal-browser bypass, share fallback, encrypted summary deletion, expired/tampered updates and rollback. Measure benign review burden, misses, battery and latency on the named devices. These checks remain unexecuted until a physical device is available.
